# Сценарные карты (scenario-map-kit)

Установка навыка: скопировать этот файл в `.claude/skills/scenario-map/SKILL.md` проекта и заменить
`<kit>` на путь к инструменту, `<maps>` — на каталог карт проекта (где `scenario-map.config.json`).

Перед работой прочитай `<kit>/AGENTS.md` (порядок работы в обоих режимах), `<kit>/docs/RULES.md`
(как писать), `<kit>/docs/FLOW_TREE_RULES.md` (нарезка) и `<kit>/docs/FORMAT.md` (поля).

## Какой режим

- Просят описать, **как работает код** → `mode: code`, источник — репозиторий (AGENTS.md, режим А).
- Просят **объяснить проект**, разобрать документацию, вики, регламенты → `mode: docs`, источник —
  документы (AGENTS.md, режим Б). Опись документации: `node <kit>/bin/scan.mjs --project=<maps> --outline`.
- Непонятно — спроси, что источник правды: код или документация.

## Обычный прогон

```bash
node <kit>/bin/scan.mjs  --project=<maps>            # сверка с источником, exit 2 при расхождениях
node <kit>/bin/build.mjs --project=<maps>            # все карты + главная, exit 1 при ошибках данных
```

Разбор отчёта `scan`:

| Раздел | Что делать |
|---|---|
| `МЕТОД ИЛИ РАЗДЕЛ ИЗМЕНИЛСЯ` | перечитать функцию или раздел, проверить шаг и ветки, поправить данные, затем `--anchors` |
| `ШАГ ОСИРОТЕЛ` | найти, куда переехала логика или текст, обновить `file` — или удалить шаг |
| `СТРОКА ВНЕ СИМВОЛА` | обновить номер строки в `file` |
| `КОДЫ ОТВЕТА БЕЗ ФИНИША` | добавить финиш «Отказ <код> — причина» или объяснить недостижимость |
| `Без привязки к источнику` | норма для `wait`, действий людей и внешних систем |

## Новый проект и новый флоу

1. Проект: `node <kit>/bin/init.mjs <maps> --mode=code|docs --title="…" --code-root=<корень кода или документации>`.
2. Прочитать источник: код входа и всех веток — или все разделы документации, которые касаются сценария.
   Условия берутся из источника дословно (код — выражение, документация — цитата «…»).
3. `node <kit>/bin/init.mjs <maps> --flow=<id> --name="<Название>"` — заготовка; переписать по `RULES.md`.
4. `scan --anchors` → `scan` → `build`; пройти чек-лист `RULES.md` §11.

## Границы

- Код и документация проекта не правятся: проблемы — в `attention` шага, решение за человеком.
- В режиме `docs` пробелы и противоречия документации не додумываются — они идут в `attention`.
- `custom_*` написал человек — не трогать. `anchor` / `fingerprint` руками не писать.
- HTML в каталоге сборки не править — перезапишется сборкой.
