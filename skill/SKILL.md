# Сценарные карты (scenario-map-kit)

Установка навыка: скопировать этот файл в `.claude/skills/scenario-map/SKILL.md` проекта и заменить
`<kit>` на путь к инструменту, `<maps>` — на каталог карт проекта (где `scenario-map.config.json`).

Перед работой прочитай `<kit>/AGENTS.md` (порядок работы), `<kit>/docs/RULES.md` (как писать),
`<kit>/docs/FLOW_TREE_RULES.md` (нарезка) и `<kit>/docs/FORMAT.md` (поля).

## Обычный прогон

```bash
node <kit>/bin/scan.mjs  --project=<maps>            # сверка с кодом, exit 2 при расхождениях
node <kit>/bin/build.mjs --project=<maps>            # все карты + главная, exit 1 при ошибках данных
```

Разбор отчёта `scan`:

| Раздел | Что делать |
|---|---|
| `МЕТОД ИЗМЕНИЛСЯ` | перечитать функцию, проверить шаг и ветки, поправить данные, затем `--anchors` |
| `ШАГ ОСИРОТЕЛ` | найти, куда переехала логика, обновить `file` — или удалить шаг |
| `СТРОКА ВНЕ МЕТОДА` | обновить номер строки в `file` |
| `КОДЫ ОТВЕТА БЕЗ ФИНИША` | добавить финиш «Отказ <код> — причина» или объяснить недостижимость |
| `Без привязки к коду` | норма для `wait`, действий людей и внешних систем |

## Новый флоу

1. Прочитать код входа и всех веток — условия берутся из кода.
2. `node <kit>/bin/init.mjs <maps> --flow=<id> --name="<Название>"` — заготовка; переписать по `RULES.md`.
3. `scan --anchors` → `scan` → `build`; пройти чек-лист `RULES.md` §11.

## Границы

- Код проекта не правится: проблемы — в `attention` шага, решение за человеком.
- `custom_*` написал человек — не трогать. `anchor` / `fingerprint` руками не писать.
- HTML в `maps/` не править — перезапишется сборкой.
