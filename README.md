# scenario-map-kit — сценарные карты для любого проекта

Инструмент документации в виде **трасс «вход → финиш с ветвлениями»**. Карта отвечает на вопросы
«что случится, если…», «почему клиент получил этот отказ» и «где в коде это решается». Данные — JSON,
результат — самодостаточные HTML-страницы: открываются двойным кликом, без сервера и сборки фронтенда.

Подходит для двух видов карт:

- **карта кода** — шаги ссылаются на `файл:строка`, сканер следит, что код не разошёлся с описанием
  (демо `examples/shop`);
- **карта процесса** — регламент без кода: продажи, поддержка, согласования (демо `examples/crm`).

Писать карты может человек, а может любой ИИ-агент: правила и формат описаны так, чтобы по ним можно
было работать без контекста. Инструкция для агентов — [`AGENTS.md`](AGENTS.md).

## Что получится

- **Главная** `maps/index.html` — разделы проекта, карточки флоу, счётчик «⚠ обратить внимание»,
  покрытие входных точек (если задан список `entrypoints`).
- **Карта флоу** `maps/<id>.full.html`:
  - селектор сценариев: первый пункт — дерево целиком, дальше каждый сценарий со своей раскладкой;
  - клик по блоку — подсветка пути от входа и паспорт справа: что происходит, условия веток, эффекты,
    фоновые задачи, замечания, ссылки на код;
  - этапы разделителями, кнопка «Сводка» (входы, исходы, замечания), светлая и тёмная тема, поиск `/`.

## Быстрый старт

Нужен только Node.js 18+. Зависимостей нет.

```bash
# посмотреть демо
node bin/build.mjs --project=examples/shop
node bin/build.mjs --project=examples/crm
# открыть examples/shop/maps/index.html и examples/crm/maps/index.html

# свой проект
node bin/init.mjs ../my-project/docs/scenario-map --title="Мой проект" --code-root=../..
node bin/build.mjs --project=../my-project/docs/scenario-map
```

`init` создаёт `scenario-map.config.json` и заготовку флоу, которая уже проходит самопроверку.
Новый флоу в существующий проект: `node bin/init.mjs <проект> --flow=checkout --name="Оформление заказа"`.

## Команды

| Команда | Что делает |
|---|---|
| `node bin/build.mjs --project=<p>` | собрать все карты и главную; самопроверка данных, exit 1 при ошибках |
| `node bin/build.mjs --project=<p> <id>` | собрать одну карту (главная не пересобирается) |
| `node bin/build.mjs … --horizontal` / `--vertical` | принудительная ориентация раскладки |
| `node bin/scan.mjs --project=<p>` | сверка с кодом: что изменилось, что исчезло, какие коды ответа без финиша; exit 2 при расхождениях |
| `node bin/scan.mjs --project=<p> --anchors` | проставить / обновить `anchor` + `fingerprint` у шагов |
| `node bin/scan.mjs --project=<p> --flow=<id>` · `--json` | один флоу · машиночитаемый отчёт |
| `node bin/init.mjs <каталог>` · `--flow=<id>` | каркас проекта · заготовка флоу |

`--project` — каталог с `scenario-map.config.json` (или путь к самому файлу). Без флага берётся текущий каталог.

## Как это устроено

```
scenario-map-kit/
├── bin/
│   ├── build.mjs          сборка: самопроверка + раскладка графа + шаблон Archify → HTML
│   ├── scan.mjs           сверка с кодом (JS/TS, PHP, Python, Go, Java, C#, Kotlin, Rust, Ruby)
│   └── init.mjs           каркас проекта и флоу
├── engine/
│   ├── config.mjs         загрузка проекта, значения по умолчанию
│   └── passport-inject.html  интерфейс карты поверх runtime Archify: панель, сценарии, зум, путь
├── vendor/archify/        рендерер Archify (MIT) — шаблон и общие модули
├── schema/                JSON Schema флоу и конфига — для IDE и агентов
├── docs/
│   ├── FORMAT.md          все поля конфига и флоу
│   ├── RULES.md           как писать: границы шага, подписи, исходы, сценарии, чек-лист
│   └── FLOW_TREE_RULES.md как нарезать систему на флоу, блоки и сценарии
├── skill/SKILL.md         навык для Claude Code
├── AGENTS.md              инструкция для любого ИИ-агента
└── examples/
    ├── shop/              интернет-магазин: код src/*.js + 2 флоу с привязкой к коду
    └── crm/               CRM: продажи и поддержка, 2 флоу без кода
```

Проект карт живёт отдельно от инструмента:

```
my-project/docs/scenario-map/
├── scenario-map.config.json   название, разделы, актёры, codeRoot, правила
├── flows/*.json               источник истины: один файл = один флоу
└── maps/                      собранные HTML (не правятся руками)
```

Три принципа:

1. **Источник истины — JSON.** HTML перезаписывается каждой сборкой; правки только во `flows/*.json`.
2. **Привязка к коду переживает рефакторинг.** `file` — место решения (`путь:строка`), `anchor` —
   функция (`путь::имя`), `fingerprint` — хэш её тела без комментариев. Сдвиг строк не ломает привязку,
   а правка логики поднимает флаг «метод изменился — перечитай шаг».
3. **Подписи пишет человек.** Автоматика не трогает `title` / `what` / `short` / `hint`. Выверенные
   формулировки защищаются полями `custom_*` — они всегда важнее дефолтных.

## Рабочий цикл

- **Новый флоу:** прочитать код входа и всех веток → `flows/<id>.json` по [`docs/RULES.md`](docs/RULES.md) →
  `scan --anchors` → `build` → открыть карту → чек-лист `RULES.md` §11.
- **После правок кода:** `scan` → перечитать помеченные шаги → поправить данные → `scan --anchors` → `build`.
- **Поправить формулировку:** правка в JSON (лучше через `custom_*`) → `build`.
- **В CI:** `scan` (exit 2 = карта отстала от кода) и `build` (exit 1 = данные сломаны).

## Демо

| Проект | Флоу | Что показывает |
|---|---|---|
| `examples/shop` | Оформление заказа и оплата · Возврат товара | привязка к коду, второй вход (webhook), ожидание 3-D Secure, фоновая задача снятия резерва, покрытие 5 из 6 входных точек, замечания ⚠ по реальным дефектам демо-кода |
| `examples/crm` | Заявка → оплаченная сделка · Обращение в поддержку | процесс без кода, циклы (повторный звонок, торг, переоткрытие тикета), таймеры SLA параллельной линией, развилки с тремя исходами |

## Ограничения

- Интерфейс карт на русском; подписи в данных — на любом языке.
- Сканер находит функции эвристикой по объявлениям, без полного разбора языка. Для сверки
  «метод правили / метод исчез» этого хватает; экзотический синтаксис может не распознаться — шаг тогда
  попадёт в «строка не внутри функции».
- Шаблон Archify подключает шрифты Google Fonts; офлайн карта работает на системных шрифтах.
