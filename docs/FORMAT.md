# Формат данных

Два вида файлов: конфиг проекта `scenario-map.config.json` и флоу `flows/<id>.json`. Машинное описание —
`schema/config.schema.json` и `schema/flow.schema.json`: пропишите `"$schema"` в файле, и IDE будет
подсказывать поля и ловить ошибки ещё до сборки. Как писать содержимое — `RULES.md`.

---

## 1. Конфиг проекта

```json
{
  "$schema": "../../scenario-map-kit/schema/config.schema.json",
  "title": "Интернет-магазин",
  "description": "Что это за система и для кого карты",
  "flows": "flows",
  "out": "maps",
  "codeRoot": "../..",
  "repository": { "url": "https://github.com/acme/shop", "revision": "main", "path": "" },
  "groups": [
    { "id": "orders", "title": "Заказы и оплата", "hint": "корзина, резерв, платёж" }
  ],
  "actors": {
    "customer": { "name": "покупатель", "type": "frontend" },
    "api": { "name": "API магазина", "type": "backend" }
  },
  "rules": { "requireFile": false },
  "layout": { "pxPerUnit": 1.45 },
  "scan": { "outcomeCodePatterns": ["status\\(([45]\\d\\d)\\)"] },
  "entrypoints": [
    { "group": "orders", "kind": "POST", "name": "/api/checkout", "anchor": "src/checkout.js::placeOrder" }
  ]
}
```

| Поле | По умолчанию | Зачем |
|---|---|---|
| `title`, `description` | — | заголовок и подзаголовок главной |
| `flows` | `flows` | каталог флоу; файлы с `_` в начале имени пропускаются |
| `out` | `maps` | куда собирать HTML |
| `codeRoot` | `.` | корень кода: относительно него пишется `file` у шагов |
| `repository` | git `origin` из `codeRoot` | ссылки «открыть в GitHub/GitLab» из паспорта; `false` — не строить |
| `groups` | один раздел `other` | разделы главной; массив или путь к JSON-файлу |
| `actors` | см. ниже | кто действует на шаге → подпись и цвет; заданный список **заменяет** умолчания |
| `rules` | см. ниже | параметры строгой самопроверки |
| `layout` | см. §4 | раскладка для всех флоу |
| `scan.outcomeCodePatterns` | `[]` | RegExp, группа 1 = код ответа; сканер сверяет коды из тела функции с заголовками финишей |
| `entrypoints` | `[]` | входные точки проекта для панели покрытия; массив или путь к JSON |

**Актёры по умолчанию:** `user`, `app`, `api`, `service`, `db`, `queue`, `external`, `payment`.
**Цвета (`type`):** `frontend` · `backend` · `database` · `cloud` · `security` · `messagebus` · `external`.
Те же цвета используют финиши: `ok` — backend, `bad` — security, `warn` — cloud, `info` — external.
Если на картах важно отличать сбой от актёра, не давайте актёрам `security`.

**`rules`:**

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `terminalTitle` | `^(Отказ\|Финиш\|Тупик\|\d{3})` | шаблон заголовка финиша у `strict`-флоу |
| `branchTitle` | `[?]$` | заголовок развилки — вопрос |
| `shortMax` / `hintMax` | 14 / 34 | длина ответа ветки и пояснения |
| `requireFile` | `false` | каждый шаг обязан ссылаться на код |

Для англоязычных карт: `"terminalTitle": "^(Rejected|Done|Dead end|\\d{3})"`.

**`entrypoints`** — список того, что в проекте вообще можно вызвать: HTTP-ручки, джобы, команды,
обработчики событий. Точка считается описанной, если `anchor` хоть одного шага любого флоу совпал с её
`anchor`. Список можно вести руками, а можно генерировать своим скриптом из роутов фреймворка
(`php artisan route:list --json`, `rails routes`, декораторы и т.п.) — формат одинаковый.

## 2. Флоу

```json
{
  "$schema": "../../scenario-map-kit/schema/flow.schema.json",
  "id": "checkout",
  "order": 1,
  "name": "Оформление заказа и оплата",
  "group": "orders",
  "tone": "ok",
  "entry": "POST /api/checkout",
  "what": "Две-три фразы для карточки на главной",
  "root": "in.checkout",
  "strict": true,
  "stages": { "check": "Проверки", "pay": "Оплата", "result": "Итог" },
  "layout": { "startZoom": 1 },
  "steps": { "in.checkout": { }, "…": { } },
  "presets": [ { } ]
}
```

| Поле | Обяз. | Смысл |
|---|---|---|
| `id` | да | совпадает с именем файла |
| `name` | да | название на языке пользователя сценария |
| `group` | да | `id` раздела из `groups` |
| `root` | да | шаг-вход, с которого начинается любой сценарий |
| `steps` | да | шаги по `id` |
| `presets` | да | сценарии (хотя бы один) |
| `order` | | порядок карточки в разделе |
| `tone` | | цвет точки на карточке: `ok` / `bad` / `warn` / `info` / `pause` |
| `entry` | | короткая подпись входа: адрес, событие |
| `what` | | текст карточки |
| `strict` | | строгие правила подписей (см. `RULES.md` §5) |
| `stages` | | этапы: ключ → подпись; шаги ссылаются полем `stage` |
| `layout` | | переопределение раскладки для этого флоу |

Имена `id` шагов — любые, удобно с префиксом вида: `in.` вход, `br.` развилка, `st.` действие,
`wait.` ожидание, `fin.` финиш, `job.` фоновая задача.

## 3. Шаг

```json
"br.stock": {
  "kind": "branch",
  "actor": "db",
  "stage": "check",
  "title": "Все товары есть на складе?",
  "code": "db.stock.findMissing",
  "file": "src/checkout/checkout.controller.js:15",
  "what": "Что здесь решается и почему это важно — 1–3 предложения",
  "effects": ["наблюдаемые следствия: записи, события, письма, ответы"],
  "note": "⏸ особый режим: отключено, на паузе",
  "attention": ["⚠ найденная проблема и её следствие"],
  "spawns": ["job.release"],
  "branches": [
    { "short": "да", "hint": "всё в наличии", "label": "полная формулировка",
      "cond": "missing.length === 0", "to": "br.promo", "tone": "ok", "paused": false }
  ]
}
```

| Поле | Смысл |
|---|---|
| `kind` | `entry` вход · `step` действие · `branch` решение · `wait` ожидание · `terminal` финиш |
| `actor` | ключ из `actors` — цвет блока и строка «Где» в паспорте |
| `title` | смысл человеческим языком; у `branch` — вопрос; у `terminal` — «Финиш: …» / «Отказ 409 — …» |
| `code` | техническая привязка мелким моно: маршрут, `Класс::метод`, имя робота CRM |
| `file` | `путь:строка` (или `путь:начало-конец`) от `codeRoot` — место решения |
| `anchor`, `fingerprint` | ставит `scan.mjs --anchors`, руками не пишутся |
| `what`, `effects`, `note`, `attention` | паспорт шага |
| `next` | следующий шаг (у `entry` / `step` / `wait`) |
| `branches` | исходы (у `branch`; у `entry` / `wait` — если у них несколько выходов) |
| `spawns` | параллельные линии: корни, недостижимые обычными переходами |
| `outcome` | только у `terminal`: `ok` / `bad` / `warn` / `info` |

**Ветка:** `to` (обязательно), `short` (ответ, ≤ 14), `hint` (почему, ≤ 34), `label` (полная фраза для
паспорта), `cond` (условие из кода или регламента), `tone`, `paused` (ветка отключена).
На ребре карты подпись собирается как `ДА · всё в наличии`.

## 4. Сценарий (пресет) и раскладка

```json
{ "name": "Оплата прошла сразу", "tone": "ok", "note": "основной путь",
  "path": ["in.checkout", "br.cart", "…", "fin.paid"],
  "sub":  ["job.release", "fin.keep"] }
```

`path` — от `root` (или другого `entry`) до `terminal` по объявленным переходам; шаги могут повторяться
(циклы). `sub` — параллельная линия от корня `spawns` до финиша.

**`layout`** (конфиг или флоу): `pxPerUnit` 1.45 (натуральный масштаб), `startZoom` 1, `rowGap` 52,
`colGap` 28, `maxVerticalWidth` 3000 (шире — горизонтальная раскладка), `phaseStyle` `divider`,
`legend` (`{ "backend": "подпись цвета" }` — иначе подпись собирается из имён актёров).

---

## 5. Ручные подписи `custom_*`

Любую подпись можно переопределить, не теряя дефолт: рядом пишется `custom_<поле>`, и показывается оно.

- шаг: `custom_title`, `custom_code`, `custom_what`, `custom_note`, `custom_effects`, `custom_attention`;
- ветка: `custom_short`, `custom_hint`, `custom_label`;
- флоу: `custom_name`, `custom_entry`, `custom_what`;
- сценарий: `custom_name`, `custom_note`.

Самопроверка проверяет эффективное значение (`custom_*`, если он есть).

---

## 6. Самопроверка сборщика

Сборка падает (exit 1) со списком ошибок, если:

- нет обязательного поля флоу, `root` не описан, `id` не совпадает с файлом;
- у шага неизвестный `kind` / `actor`, пустой `what`, у финиша есть переходы или нет `outcome`;
- у не-финиша нет ни `next`, ни `branches`; переход ведёт в неизвестный шаг;
- `spawns` ведёт в шаг, достижимый обычными переходами, или линия запускает саму себя;
- шаг недостижим ни от `root`, ни от корней `spawns`; во флоу нет ни одного `outcome: ok`;
- сценарий начинается не с входа, рвётся (нет перехода между соседями), кончается не финишем, без `note`;
- у `strict`-флоу: развилка не вопрос, ветка без `short` / `hint` / `cond` или длиннее лимита, финиш не
  по шаблону, техническое имя в заголовке без `code`;
- флоу ссылается на раздел, которого нет в `groups`; у `entrypoints` нет `anchor` или неизвестный раздел.
