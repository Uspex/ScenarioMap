# scenario-map-kit — подробное руководство

**Сценарные карты «вход → финиш с ветвлениями» для любого проекта — по коду или по документации.**

Карта отвечает на вопросы «что случится, если…», «почему клиент получил этот отказ» и «где это
решается — в коде или в документе». Сценарии описываются в JSON; на выходе получаются самодостаточные
интерактивные HTML-страницы, которые открываются двойным кликом, без сервера и сборки фронтенда.
Нужен только Node.js 18+, зависимостей нет.

Карты может писать человек, а может любой ИИ-агент (Claude Code, Codex, Cursor, Gemini и т.д.): правила
и формат написаны так, что по ним можно работать без контекста. Инструкция для агентов —
[`AGENTS.md`](../AGENTS.md), готовый навык Claude Code — [`skill/SKILL.md`](../skill/SKILL.md).

## Демо

Откройте [`index.html`](../index.html) в корне — там все примеры (они же собраны в `demo/`):

| Демо | Режим | Что показывает |
|---|---|---|
| [Интернет-магазин](../demo/shop/index.html) | карта кода | шаги привязаны к функциям `examples/shop/src`, второй вход (webhook), 3-D Secure, фоновая задача снятия резерва, покрытие 5 из 6 HTTP-ручек, ⚠ по реальным дефектам демо-кода |
| [Онлайн-школа «Академия»](../demo/academy/index.html) | карта по документации | кода нет — только `examples/academy/docs/*.md`; условия веток — цитаты, покрытие 9 из 11 разделов, ⚠ — противоречия между документами и пробелы в них |
| [CRM продаж и поддержки](../demo/crm/index.html) | карта процесса | регламент без кода: циклы (повторный звонок, торг, переоткрытие тикета), таймеры SLA параллельной линией |

## Два режима

| | Карта кода — `mode: code` | Карта по документации — `mode: docs` |
|---|---|---|
| Что изучается | репозиторий: роуты, обработчики, джобы, все ветки до `return` / `throw` | README, вики, регламенты, спецификации: `.md` `.rst` `.adoc` `.txt` |
| Зачем | увидеть все исходы кода и где каждый решается | объяснить проект человеку, который не хочет читать всё, и найти, где документация противоречит себе или молчит |
| Шаг ссылается на | `src/checkout.js:15` → функцию `placeOrder` | `docs/billing.md:16` → раздел «Списание» |
| Условие ветки | выражение из кода: `missing.length === 0` | цитата: `«не ниже чем на 70 баллов из 100»` |
| `scan` предупреждает | функцию изменили — перечитай шаг | текст раздела изменили — перечитай шаг |
| Покрытие | какие входные точки кода описаны | какие разделы документации объяснены |

Режимы можно смешивать: шаг карты кода может сослаться на раздел регламента, шаг карты документации — на
функцию. Сканер понимает обе ссылки.

## Что получится

- **Главная** `index.html` проекта карт — разделы, карточки флоу, счётчик «⚠ обратить внимание»,
  покрытие входных точек или разделов документации.
- **Карта флоу** `<id>.full.html`:
  - селектор сценариев: первый пункт — дерево целиком, дальше каждый сценарий со своей раскладкой;
  - клик по блоку — подсветка пути от входа и паспорт справа: что происходит, условия веток, эффекты,
    фоновые задачи, замечания, ссылки на код или документ (с переходом в GitHub/GitLab, если есть git);
  - этапы разделителями, кнопка «Сводка» (входы, исходы, замечания), светлая и тёмная тема, поиск `/`.
- **Шапка на всех страницах:** кнопка «назад» (карта → главная проекта → куда укажет `back` в конфиге) и
  переключатель светлой/тёмной темы; выбор темы общий для главной и карт.

## Быстрый старт

```bash
git clone <url этого репозитория> scenario-map-kit
cd scenario-map-kit

# пересобрать демо и сверить их с источниками
npm run check

# карта кода своего проекта
node bin/init.mjs ../my-project/docs/scenario-map --title="Мой проект" --code-root=../..
node bin/build.mjs --project=../my-project/docs/scenario-map

# карта по документации своего проекта (codeRoot — каталог с документацией)
node bin/init.mjs ../my-project/docs/scenario-map --mode=docs --title="Мой проект" --code-root=..
node bin/scan.mjs --project=../my-project/docs/scenario-map --outline    # оглавление документации
node bin/build.mjs --project=../my-project/docs/scenario-map
```

`init` создаёт `scenario-map.config.json` и заготовку флоу, которая уже проходит самопроверку.
Новый флоу в существующий проект: `node bin/init.mjs <проект> --flow=checkout --name="Оформление заказа"`.

## С ИИ-агентом

Дайте агенту доступ к этому каталогу и к проекту и попросите, например:

- «Прочитай `scenario-map-kit/AGENTS.md` и построй сценарные карты для этого репозитория» — режим А;
- «Прочитай `scenario-map-kit/AGENTS.md` и объясни проект картами по документации в `docs/`» — режим Б.

Агент сам сделает опись (входные точки кода или оглавление документации), нарежет сценарии, заполнит
`flows/*.json`, привяжет шаги к источнику и проверит себя командами `scan` и `build`. Для Claude Code
скопируйте `skill/SKILL.md` в `.claude/skills/scenario-map/SKILL.md` своего проекта. Если у агента нет
доступа к файлам, в `AGENTS.md` есть готовый промпт для чата.

## Команды

| Команда | Что делает |
|---|---|
| `node bin/build.mjs --project=<p>` | собрать все карты и главную; самопроверка данных, exit 1 при ошибках |
| `node bin/build.mjs --project=<p> <id>` | собрать одну карту (главная не пересобирается) |
| `node bin/build.mjs … --horizontal` / `--vertical` | принудительная ориентация раскладки |
| `node bin/scan.mjs --project=<p>` | сверка с кодом и документацией: что изменилось, что исчезло, какие коды ответа без финиша; exit 2 при расхождениях |
| `node bin/scan.mjs --project=<p> --anchors` | проставить / обновить `anchor` + `fingerprint` у шагов |
| `node bin/scan.mjs --project=<p> --outline[=<каталог>]` | оглавление документации под `codeRoot`: разделы с готовыми `file` и `anchor` |
| `node bin/scan.mjs --project=<p> --flow=<id>` · `--json` | один флоу · машиночитаемый отчёт |
| `node bin/init.mjs <каталог> [--mode=code\|docs]` · `--flow=<id>` | каркас проекта · заготовка флоу |
| `npm run build:demo` · `npm run scan:demo` · `npm run check` | пересобрать демо в `demo/` · сверить · и то и другое |

`--project` — каталог с `scenario-map.config.json` (или путь к самому файлу). Без флага берётся текущий каталог.

## Как это устроено

```
scenario-map-kit/
├── index.html             витрина демо — открыть в браузере (подходит для GitHub Pages)
├── demo/                  собранные демо-карты: shop/, academy/, crm/
├── bin/
│   ├── build.mjs          сборка: самопроверка + раскладка графа + шаблон Archify → HTML
│   ├── scan.mjs           сверка с источником: код (JS/TS, PHP, Python, Go, Java, C#, Kotlin, Rust, Ruby)
│   │                      и документация (Markdown, reStructuredText, AsciiDoc); оглавление --outline
│   └── init.mjs           каркас проекта (--mode=code|docs) и флоу
├── engine/
│   ├── config.mjs         загрузка проекта, режимы, значения по умолчанию
│   └── passport-inject.html  интерфейс карты поверх runtime Archify: панель, сценарии, зум, путь
├── vendor/archify/        рендерер Archify (MIT) — шаблон и общие модули
├── schema/                JSON Schema флоу и конфига — для IDE и агентов
├── docs/
│   ├── FORMAT.md          все поля конфига и флоу, режимы
│   ├── RULES.md           как писать: границы шага, подписи, исходы, сценарии, чек-лист
│   └── FLOW_TREE_RULES.md как нарезать систему на флоу, блоки и сценарии
├── skill/SKILL.md         навык для Claude Code
├── AGENTS.md              инструкция для любого ИИ-агента: режим кода и режим документации
└── examples/              исходники демо: конфиг + flows/*.json
    ├── shop/              интернет-магазин: код src/*.js + 2 флоу с привязкой к коду
    ├── academy/           онлайн-школа: документация docs/*.md + 2 флоу с привязкой к разделам
    └── crm/               CRM: продажи и поддержка, 2 флоу без источника-файла
```

Проект карт живёт отдельно от инструмента:

```
my-project/docs/scenario-map/
├── scenario-map.config.json   название, режим, разделы, актёры, codeRoot, правила
├── flows/*.json               источник истины: один файл = один флоу
└── maps/                      собранные HTML (не правятся руками)
```

Три принципа:

1. **Источник истины — JSON.** HTML перезаписывается каждой сборкой; правки только во `flows/*.json`.
2. **Привязка к источнику переживает правки.** `file` — место решения (`путь:строка`), `anchor` —
   функция или раздел (`путь::имя`), `fingerprint` — хэш его тела. Сдвиг строк не ломает привязку, а
   правка логики или текста поднимает флаг «изменилось — перечитай шаг».
3. **Подписи пишет человек.** Автоматика не трогает `title` / `what` / `short` / `hint`. Выверенные
   формулировки защищаются полями `custom_*` — они всегда важнее дефолтных.

## Рабочий цикл

- **Новый флоу:** прочитать источник (код входа и всех веток или все разделы документации по сценарию) →
  `flows/<id>.json` по [`docs/RULES.md`](RULES.md) → `scan --anchors` → `build` → открыть карту →
  чек-лист `RULES.md` §11.
- **После правок кода или документации:** `scan` → перечитать помеченные шаги → поправить данные →
  `scan --anchors` → `build`.
- **Поправить формулировку:** правка в JSON (лучше через `custom_*`) → `build`.
- **В CI:** `scan` (exit 2 = карта отстала от кода или документации) и `build` (exit 1 = данные сломаны).

## Ограничения

- Интерфейс карт на русском; подписи в данных — на любом языке.
- Сканер находит функции эвристикой по объявлениям, без полного разбора языка. Для сверки
  «метод правили / метод исчез» этого хватает; экзотический синтаксис может не распознаться — шаг тогда
  попадёт в «строка не внутри функции».
- Разделы документации определяются по заголовкам; документы без заголовков считаются одним разделом.
  Переименование заголовка меняет `anchor` — `scan` покажет такой шаг как осиротевший.
- Шаблон Archify подключает шрифты Google Fonts; офлайн карта работает на системных шрифтах.
